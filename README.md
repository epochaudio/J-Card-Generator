# 带藏 · TapeFolio 📼

为磁带收藏者设计的封面制作工具。原名“磁带封面生成器 / J-Card Genesis / Tape Cover Generator”。

品牌名称与图标已更新；既有 2.0.1 Release 为更名前安装包，新品牌安装包尚未发布。

当前版本：**2.0.1**。安装包与更新说明见 [v2.0.1 Release](https://github.com/epochaudio/J-Card-Generator/releases/tag/v2.0.1)。

## 源码更新：AI 完整配色（待发布）

在“智能搭配”中，视觉模型直接观察封面原图，自主设计正面、背面曲目区、脊背和折页的完整配色，不受三套预设或图片取色结果限制。原始封面图片保持原样。

- **分区与文字配色**：分别指定各面板背景、标题、艺术家、副标题、曲名、时长、备注，以及标语、圆标、分隔线和边框颜色。
- **检查与修订**：按文字实际底色检查对比度；有效方案不足三套时，最多向同一模型追加一次修订请求。仍未通过的方案不展示，程序不擅自替换颜色。
- **完整保存**：支持整套配色锁定、预览、应用、撤销、草稿及保存恢复；原有三套预设继续作为手动选项。

使用入口：上传主封面 → “智能搭配” → “生成三套搭配” → 放大检查 → “应用这套”。详见[使用说明](HELP.md#ai-完整配色工作区更新)。

此功能尚未包含在现有 v2.0.1 安装包中。已验证模拟模型响应下的实际渲染、保存恢复和 PNG 导出，尚未进行真实模型调用；新完整色板需使用包含本次更新的应用打开。

## v2.0.1 更新（2026-09-08）

- **智能搭配**：基于封面原图与内容，一次生成“延续原封面”“突出标题”“阅读清晰”三个方向，支持字体／配色锁定、独立放大预览、应用与撤销。只展示通过本地检查的有效组合，不足三套时明确说明。[使用说明](HELP.md#智能搭配第一版)
- **DeepSeek 内测视觉支持**：可配置 `deepseek-v4.1-flash-expires-on-0910`，沿用原 API 地址和密钥。文本、图片生成、视觉分析分别选择；普通 V4 Flash 不自动视为视觉模型，内测失效也不自动切换型号。[配置说明](HELP.md#使用-deepseek-v41-flash-内测测试智能搭配)
- **封面智能补足信息**：上传主封面后识别专辑线索，自动搜索 MusicBrainz；匹配不唯一时选择专辑与发行版本，再逐项核对导入。默认只补空字段，替换已有内容需勾选，两张封面和未选内容保留。[使用说明](HELP.md#从封面智能补足专辑信息)
- **预览与导出修复**：候选图与 PNG 导出等待内嵌字体实际绘制，修复正文可能缺失的问题；各预览的滤镜和裁切标识独立。
- **保存兼容**：作品格式保持 v2，AI 设置为 v3；旧配置的视觉功能默认不启用，候选方案和识别结果不会自动写入作品。

92 项自动测试及新增功能的模拟接口交互验证通过；真实模型效果、实际账户可用性和实体打印仍待验证。实施细节见 [智能搭配维护记录](MAINTENANCE.md#f10-ai-design) 与 [智能补足维护记录](MAINTENANCE.md#f11-cover-enrichment)。

**J-Card Genesis** 是一款专为磁带收藏家和 DIY 爱好者设计的桌面应用程序。它结合了现代 AI 技术，帮助你轻松制作出专业、美观的实体磁带封面（J-Card / U-Card），并支持从搜索、导入、排版到导出的完整桌面工作流。

## 当前版本状态

已实现项目保存、打开、另存为和自动草稿恢复。`.jcard` 文件包含曲目、双封面、排版、配色及录音信息，不包含 API Key；重新打开会保留原录音日期。新建、打开其他作品或关闭窗口前会提醒未保存修改。

桌面版在实际写入成功后标记已保存；浏览器开发模式通过下载交付文件，并继续保留草稿。使用方法见 [HELP.md](./HELP.md#项目保存与恢复)。当前源码版本为 `2.0.1`，新增智能搭配与封面智能补足。安装包见 [v2.0.1 版本页面](https://github.com/epochaudio/J-Card-Generator/releases/tag/v2.0.1)。

作品格式为 **版本 3**，保存完整色板、标题尺寸及纸纹状态。封面设计统一采用一套排版规则，不再提供排版版本切换。本次为跨版本更新，不支持版本 1、2 作品文件，也不提供旧作品自动转换。

详细实现与验证范围见 [维护文档](./MAINTENANCE.md) 和 [审美改进实施记录](./DESIGN_IMPROVEMENT_PROPOSAL.md#11-实施与验证记录2026-09-08)。页面中的历史截图展示旧版界面；当前字体、配色与布局入口位于右侧“封面设计”。

## ✨ 主要功能 (Key Features)

*   **字体与排版系统 (Typography System)**:
    *   **七套字体搭配**：现代、胶片、手记、骇客、素体、编辑、重工。随包字体可离线加载，无需在线字体镜像。
    *   **编辑主题**：Noto Serif SC 中英文衬线标题，搭配 Inter / Noto Sans SC 黑体正文。
    *   **手记主题**：保留手写标题和标语，曲目正文使用清晰黑体。
    *   **稳定文字层级**：标题支持克制、均衡、醒目三档，结合真实字高和混排测量自适应换行；艺术家与标语保持独立层级。
    *   **三种正面布局**：经典居中、编辑左齐、双面颠倒。编辑左齐采用图片留边，文字共享左边线。
    *   **设计入口**：右侧“封面设计”提供字体、配色和布局小样，顶部“设计”按钮可跳转。

### MusicBrainz 搜索与核对导入

以下为自 `1.6.1` 起已有的功能，2.0.1 在此基础上增加上述视觉辅助流程。

*   **逐步核对**：搜索专辑 → 选择发行版本 → 核对署名、日期、封面和分面 → 确认导入。搜索和发行列表支持加载更多，不自动代选版本。
*   **完整署名**：保留合作署名及连接词；演奏者、指挥、作曲者按明确关系记录，成品署名可选完整署名或明确演奏者。制作人、录音及混音师继续用于录音资料区域。
*   **版本与来源**：分别保存首发日期与所选版本日期。封面优先对应所选版本，回退到专辑组会提示；来源、原碟号和原曲号随 `.jcard` 保存。
*   **作品结构**：沿明确的作品父子关系整理乐章，保留多个作品和作曲者。关系缺失时保留原曲名，不能仅因存在 Work 关系把爵士判为古典；内容模式可手动选择。
*   **分面与失败保护**：按每面容量、时长和连续作品边界建议分面，不重排曲目。失败、取消或过期请求不改变当前作品；成功导入前分别确认主封面和第二封面的处理。
*   **智能 AI 驱动**:
    *   支持 **阿里云百炼、火山引擎和 DeepSeek**，用于曲目文本导入、标题建议、标语和封面提示词生成。
    *   **颗粒度 AI 控制**:
        *   **✨ 文案生成**: 独立的 "魔法棒" 按钮，一键生成 1-3 句俳句式短诗文案 (拒绝营销词)。
        *   **🎨 提示词生成**: 独立的 "AI 生成提示词" 按钮，自动分析曲风并从 4 种特定画风 (水彩/杂志/日记/平面) 中锁定一种，生成可落地的绘画指令。
    *   集成 **通义万相 (Wanx)**，一键生成高质量、富有艺术感的封面图。
*   **主题系统 (Theme System)**:
    *   **AI 完整配色（源码更新）**：直接看图设计四个面板与各类文字的颜色，按实际底色检查可读性，支持整套锁定与保存。
    *   **完整色板**：暖纸档案、暖暗唱片、冷灰编辑，统一设置背景、主文字、辅助文字、分隔线与强调色。
    *   **可控微调**：强调色可手动修改或从封面推荐，预设色板不会因上传图片自动被覆盖；小文字强调色会调整到可读的深浅。
    *   **轻微纸纹**：封面排版默认关闭，可单独开启。
    *   **保留背景模式**：深色、浅色、封面背景、图片取色仍可选择。
    *   **🌑 Dark**: 经典的深色模式，专业冷静。
    *   **☀️ Light**: 纯白背景，极简主义，适合白纸打印。
    *   **🖼️ Cover**: 沉浸式封面背景，自动应用高斯模糊滤镜。
    *   **🎨 Color**: 智能取色，自动提取封面主色调作为背景，并智能反转文字颜色。
*   **曲目编辑与导入**:
    *   支持手动编辑曲目标题、艺术家、时长和备注。
    *   支持 **Side A / Side B 各自增删曲目**，并自动重算面时长。
    *   非古典模式支持通过拖拽把手进行 **同面重排** 与 **A/B 面跨侧移动**。
    *   支持从 **MusicBrainz** 数据库直接搜索并填充专辑信息。
    *   支持 **智能文本粘贴**：可直接粘贴 Spotify、网易云音乐等平台的曲目文本，AI 自动解析提取。
*   **背面智能密度控制 (Back Density Control)**:
    *   **Print-First Header**: 主封底现在以统一的 `SIDE A / SIDE B` 分区标题驱动阅读节奏，side 总时长与标题形成完整 header，而不是继续作为远端弱提示。
    *   **古典模式自动折叠**: 当作品分段过多时，背面会在完整分曲、节选分曲、作品摘要与仅作品名之间自动降级，避免文字页溢出。
    *   **非古典分面编号**: `STANDARD / COMPILATION` 模式下，`SIDE A / SIDE B` 的曲目编号各自从 `01` 开始，不再延续全专辑的一贯制编号。
    *   **非古典 Note-Aware 策略**: 在 `STANDARD / COMPILATION` 模式下，系统优先保留曲名与备注，再根据空间压力逐步隐藏 `artist / duration`；在本轮打印优先调优后，`note / 单曲尾部时长` 会更早退让，以换取更可靠的成品可读性。
    *   **真实字体测量驱动**: 所有降级决策基于实际字体折行与可用高度计算，而不是单纯按条目数粗暴裁剪。
*   **不仅仅是 J-Card**:
    *   支持 **4 折页布局 (U-Card)**，提供比传统 J-Card 更多的展示空间，完美包裹磁带盒。
    *   提供 **标准**、**古典**、**合辑** 三种排版模式。
    *   最左侧 `Short Back (Fold-in)` 现已支持独立模式选择，可在 `档案信息 / 紧凑曲目` 之间切换；其中 `紧凑曲目` 会根据标题长度与空间压力动态调整每面显示数量，并在高密度时接受“少显示 1 首、换取更大字号”的 print-first 取舍。
*   **专业打印适配**:
    *   专为 **Canon SELPHY CP1500** 等 6 寸 (4R, 100x148mm) 照片打印机优化。
    *   支持导出 **SVG** (矢量) 和 **PNG** (高清) 格式。
    *   本轮对 `Back / Short Back / Spine / Reversible Front Markers` 做了小字下限抬升，整体更偏向“印出来能读”而不是“信息尽量全塞满”。
*   **档案级元数据 (Archival Metadata)**:
    *   支持记录 **音源 (Source)**、**录音设备 (Equipment)** 和 **录制日期**，并持久化保存。
*   **稳定性与安全性改进**:
    *   Electron 已启用 `contextIsolation` 并关闭 `nodeIntegration`。
    *   三家服务商的 API Key 独立配置，桌面版使用系统加密存储；旧阿里密钥迁移成功前保留原数据。
    *   复杂 SVG 预览采用输入防抖，减少频繁重绘带来的卡顿。

## 📖 使用指南 (User Guide)

### 配置 AI 服务（使用 AI 功能时需要）
支持阿里云百炼、火山引擎（火山方舟）和 DeepSeek 的普通 API。DeepSeek 支持文本及指定内测模型的视觉分析，图片生成服务商可选阿里云或火山方舟。手动编辑、作品保存和打印不要求密钥。
1. 点击右上角 **AI 服务设置**，在各服务商标签中分别输入普通 API Key。
2. 点击 **获取模型**，在文本、图片或视觉模型下拉框中搜索、选择；阿里云需填写北京地域的 **业务空间 ID**。阿里云保留原文本默认，DeepSeek 默认 `deepseek-v4-flash`。也可在模型的 **保存值** 输入框直接填写 ID；下方搜索框仅筛选列表，不会保存为模型。火山方舟 `ep-…` 接入点仅用于已适配的文本／图片生成能力。
3. 点击 **保存设置**，看到保存成功后生效；关闭未保存的设置会取消编辑。清空某家密钥并保存，只删除该家的密钥。

### 2. 制作流程
1.  **输入信息**:
    *   **文本导入 (推荐)**: 点击 "粘贴文本"，粘贴任意格式的曲目列表（如网易云/Spotify 歌单文本），AI 会自动识别。
    *   **MusicBrainz**: 输入专辑名及可选艺术家，选择发行版本，核对预览后确认导入。
    *   **手动输入**: 在右侧面板修改专辑信息、元数据与单曲字段；支持直接新增或删除曲目。
    *   **非古典拖拽整理**: 在 `标准 / 合辑` 模式下，可直接拖拽右侧曲目卡片左侧把手，快速调整同面曲序，或在 A/B 面之间移动曲目。
2.  **单项 AI 辅助**:
    *   **标题建议**: 点击专辑标题旁的魔法棒，按曲目生成标题。
    *   **Slogan**: 点击"封面标语"旁的 ✨ 按钮，生成私密感短诗。
    *   **Prompt**: 点击"AI 图片提示词"旁的按钮，生成适配曲风的绘画指令。
3.  **生成封面**:
    *   点击 **"生成封面"**，AI 将根据提示词生成艺术封面（约需30-60秒）。
    *   或点击 **"上传 (Upload)"** 使用本地图片（自动零裁剪填充）。
4.  **调整设计与布局**:
    *   在右侧 **封面设计** 选择字体搭配、完整色板与强调色。
    *   选择 **经典居中 / 编辑左齐 / 双面颠倒**；单封面封面排版支持三档标题尺寸与轻微纸纹开关。
    *   切换 `标准` / `古典` / `合辑` 模式。
    *   `古典模式` 特性：自动归类乐章，背面展示详细录音设备与时间信息 (Tech Specs)。
    *   `Short Back 模式` 可独立控制最左侧折页显示内容，不会改写主封底的曲序来源。
    *   `古典模式` 目前不支持拖拽排序；`标准 / 合辑` 模式支持拖拽重排，并会即时联动背面排版与面时长。
5.  **保存与导出**:
    *   使用 **保存作品 / 另存为** 保留可继续编辑的 `.jcard` 文件；SVG、PNG 是成品输出。
    *   点击 **导出 SVG** 或 **导出 PNG**。导出会等待字体加载并嵌入当前主题所需的随包字体；含中文字体的 SVG 文件可能较大。
    *   封面排版出现正面或背面溢出提示时，需调整内容后再导出。紧凑显示可能省略部分辅助信息，完整内容仍保存在作品文件中。

### 3. 功能详解
*   **Toolbar**: `旋转箭头`图标可一键重置项目（保留 API Key、录音设备与音源设置）。顶部“设计”按钮跳转到右侧设计面板，背景模式在该面板内切换。
*   **Spine Layout**:
    *   **Note Upper**: 脊部顶部备注（常填 `STEREO / MONO`、年份、录音日期等）。
    *   **Note Lower**: 脊部底部备注（常填版权、版本信息或自定义说明）。
    *   **双轨底部元信息**: 当 `artist` 与 `Note Lower` 同时存在时，系统会将两者放入平行双轨中，`artist` 保持主轨居中，`Note Lower` 退到外侧副轨，避免底部重叠。
    *   **输入上限**: `Note Lower` 建议控制在 `12` 字内，系统会在输入层限制为最多 `16` 个可见字符。
    *   支持“极简脊部”、“强制大写”与可选的**脊部短标题**兜底策略。
    *   为避免打印时出现过细过小的脊部说明字，系统在空间紧张时会更早进入 `no-notes / artist-only` 这类保守模式。
*   **Track Ordering**:
    *   非古典模式下，曲目卡片左侧新增拖拽把手。
    *   支持同侧排序与跨 `SIDE A / SIDE B` 移动。
    *   拖拽后会自动重算 `SIDE A / SIDE B` 总时长，并实时刷新预览顺序。
*   **Back Overflow Handling**:
    *   古典模式会自动折叠作品层级，避免多分曲作品挤爆背面。
    *   非古典模式会优先保留 `标题 + note`，再视密度隐藏 `artist / duration`；在打印优先策略下，局部辅助信息会比以前更早退让。
    *   长作品名的古典模式在极端密度下可能更早从完整分曲回退到摘要级别，但仍保持“作品结构优先”的阅读逻辑。
*   **Data Persistence**: 录音设备 (Equipment) 和 音源 (Media Source) 会自动保存，方便制作系列磁带。

## ❓ 常见问题 (FAQ)

**Q: 为什么生成图片很慢？**
A: 高清图像模型 (Wanx 2.5) 计算量大，通常需要 30-60 秒，请耐心等待。

**Q: 生成的图片不满意？**
A: 可手动修改 "AI 图片提示词" 框中的描述（如增加“赛博朋克”等关键词），再点击生成。

**Q: MusicBrainz 搜不到？**
A: 建议直接 Google 搜索专辑曲目列表，复制文本后使用软件的 **"粘贴文本"** 功能导入，这是最高效的方式。

## 🖨️ 打印与规格说明

导出画布为 **1748 x 1181 px**。按 300 DPI 打印时，对应约 **148 x 100 mm**，适合 Canon SELPHY CP1500 等 6 寸 / 4R 横向照片打印流程。

面板从左到右依次为 **Short Back / Fold-in (200 px)**、**Spine (150 px)**、**Front (780 px)**、**Back (618 px)**。打印时请选择 **适配尺寸**，不要选择 **充满**，避免二次放大后裁掉边缘或折线。

功能增加建议、优先级、设计边界与验收规划见 [维护与功能规划](./MAINTENANCE.md)。设计方案及已完成批次见 [审美改进实施记录](./DESIGN_IMPROVEMENT_PROPOSAL.md)。未实施的维护事项仍为待确认建议。

```bash
# 克隆仓库
git clone https://github.com/epochaudio/J-Card-Generator.git
cd J-Card-Generator
npm ci

# 启动开发
npm run electron:dev

# 运行自动测试
npm test

# 构建前端（包含字体资源校验）
npm run build

npm run electron:build

# 单独构建 macOS arm64 DMG
npm run electron:build:mac-arm64:dmg

# 构建 Windows x86-64（x64）NSIS 安装包
npm run electron:build:win-x64
```

### 构建说明

- 三个打包入口统一执行：环境及版本检查 → 自动测试 → 字体检查与前端构建 → 平台打包 → 安装包验证 → 交付。
- 首次准备环境使用 `npm ci`。脚本核对已安装的直接依赖与锁文件；版本不符时停止，避免使用不同依赖生成同版本安装包。
- 新产物进入 `dist_electron_builds/<版本>-<目标>-<时间>-<唯一编号>/`，包含安装包、同名 `.sha256` 和 `build-record.json`。旧本地产物保留在原目录；公开版本以 Releases 附件为准。
- 每次构建先写临时目录，所有检查通过后才整体移入交付目录，不覆盖旧包。失败时清理本次临时文件；若磁盘映像卸载失败，会保留现场并提示处理。
- 构建记录包含源码提交、未提交状态及文件摘要、工具版本、产物摘要和检查结果。本地允许未提交修改；构建期间修改源码会使本次交付失败。CI 要求干净工作区，且标签、源码提交与应用版本一致。
- Mac 验证 DMG 完整性、只读挂载后的版本、arm64 架构、签名与包内资源；Windows 验证 NSIS 完整性、解出的资源和 x64 架构。此类检查不替代实机安装测试。
- macOS 仍使用临时签名，Windows 仍未签名。双平台入口仅支持 macOS；Windows 主机使用单独的 Windows 入口。
- 同一工作区只允许一次打包。如进程被强制结束遗留 `dist_electron_builds/.build-lock`，确认没有构建进程后才手动移除该锁目录。

### 构建与公开发布分离

1. 提交待发布源码及对应的 `docs/releases/<版本>.md`，创建与版本一致的标签。
2. 手动运行 **Build verified desktop installers**，指定该标签。两个平台分别使用对应系统构建，完成校验后仅保存 Actions 文件，保留 30 天，不创建或公开 Release。
3. 需要公开时，另行手动运行 **Publish verified desktop installers**，填写同一标签、成功构建的运行 ID，并输入 `PUBLISH`。
4. 发布流程核对构建来源、源码摘要和本地产物，再上传至草稿，重新下载并核对摘要后才公开。已有公开版本或包含文件的草稿会被拒绝覆盖；部分上传失败会保留草稿，需检查处理后再试。

构建和发布均通过 GitHub 手动工作流执行；仅推送源码不会自动公开安装包。版本说明来自对应文档，不使用固定版本文案。
